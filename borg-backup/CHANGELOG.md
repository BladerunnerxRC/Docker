# Changelog

All notable changes to the borg-backup scripts in this folder. Versions follow
[Semantic Versioning](https://semver.org/): a major version changes how scripts are deployed
or what a host needs, a minor version adds features, a patch fixes bugs.

The version is kept in [`VERSION`](VERSION) and in the `SURVEY_VERSION` / `PULL_VERSION`
variables of `borg-backup-survey.sh` and `pull-borg-scripts.sh`. Scripts generated by the
survey name the survey version in their header.

## [2.0.0] - 2026-10-09

The first versioned release. Everything before it was unversioned and counts as 1.x.

### Breaking

- Prep scripts are deployed with `deploy-borg-prep-<host>.sh` instead of being copied to
  `/usr/local/sbin` by hand. It refuses the Borg UI wrapper, CRLF line endings, syntax errors
  and the wrong host, shows a diff and asks first. Copying the wrapper by mistake is what broke
  optiplex-three's pre-backup step on 2026-10-06.
- The deploy and pull scripts need the Synology share mounted at `/mnt/backups`. Without it
  they change nothing.
- Deploy backups moved to `/mnt/backups/borg-script-backups/<host>/<YYYYmmdd-HHMMSS>/`, last 10
  kept per host. Older backups in `/var/backups/borg-prep-scripts/` are not used by `--rollback`.
- Generated prep scripts differ from 1.x ones: they warn and continue when a copy or dump
  fails, where 1.x aborted the run on a failed rsync or skipped failures silently. Review the
  deploy diff when replacing a 1.x script.

### Added

- `deploy-borg-prep-<host>.sh` (generated by the survey; optiplex-three's is checked in):
  `--test`, `--rollback`, `--list`, `--backup-only`; exit 3 when the y/N prompt is declined.
- `pull-borg-scripts.sh`: downloads a host's prep and deploy scripts, the survey, the
  README, itself, `VERSION` and `CHANGELOG.md` from GitHub, checks them, and saves a dated copy
  with the commit in `/mnt/backups/borg-script-backups/<host>/github-pulls/`. Files from `main`
  go to `~/borg-backup-scripts`, files from another branch to `~/borg-backup-scripts-<branch>`.
- Prep script summary: timestamped progress, warnings on stderr, and a per-section table
  (files, size, time, warnings) printed at the end and saved as `metadata/prep-summary.txt`.
  In the optiplex-three script and in every generated script.
- Survey: after generating, an interactive root run on the target host offers to back up
  the installed prep script or deploy the new one.
- Survey: home directories of login users (UID 1000+ under `/home`) are listed in
  `REPORT.md` and copied into the snapshot, without `~/.cache` and without mounts inside them.
  Nothing is copied twice when homes, app dirs and compose projects overlap.
- `--version` on the survey and pull scripts.
- README: architecture, backup, deploy and restore diagrams.

### Changed

- rsync exit 24 (files vanished during the copy) is no longer reported as a problem.
- Directories of 10G or more, or whose size the survey could not measure in 20 seconds, are
  generated commented out and show as `SKIP` in the summary.
- k3s config, manifests and token are copied whenever they exist, even when the `k3s`
  command is not on PATH.

### Fixed

- `--name` and `--address` are validated before they are written into generated scripts.
- Two deploys in the same second no longer overwrite each other's backup.
- A directory size printed on two lines no longer breaks the generated prep script.
- The survey checklist said `chmod 700`; it is 750, matching the deploy script.
