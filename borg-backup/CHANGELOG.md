# Changelog

All notable changes to the borg-backup scripts in this folder. Versions follow
[Semantic Versioning](https://semver.org/): a major version changes how scripts are deployed
or what a host needs, a minor version adds features, a patch fixes bugs.

The version is kept in [`VERSION`](VERSION) and in the `SURVEY_VERSION` / `PULL_VERSION`
variables of `borg-backup-survey.sh` and `pull-borg-scripts.sh`. Scripts generated by the
survey name the survey version in their header.

## [3.0.0] - 2026-10-19

Hosts no longer need the Synology backup share. Script backups stay on the host and reach Borg
inside the prep snapshot, so a backed-up host needs no write access to its own repo share.

### Breaking

- `deploy-borg-prep-<host>.sh` keeps rollback copies in
  `/var/backups/borg-script-backups/<host>/<YYYYmmdd-HHMMSS>/` on the host (last 10) and no
  longer needs `/mnt/backups`. Backups made by 2.0.0 on the share are shown by `--list` when
  reachable but are not used by `--rollback`.
- `pull-borg-scripts.sh` writes to `~/scripts/borgbackup` (`~/scripts/borgbackup-<branch>` for
  other branches) instead of `~/borg-backup-scripts`, needs no `sudo`, and keeps no dated copies
  on the share. `SOURCE.txt` in the folder records the branch and commit.

### Added

- Prep scripts copy themselves to `metadata/prep-script.sh` and the deploy script's rollback
  copies to `metadata/script-backups/`, so every archive holds the script that made it.
- Survey: Checkmk containers (`checkmk/check-mk-*`) get an `omd backup` of their site
  (`CMK_SITE_ID`, default `cmk`) to `databases/<container>-<site>-<version>-<YYYYmmdd-HHMMSS>.omd.tar`, uncompressed so Borg
  can deduplicate it, renamed into place only when `omd backup` succeeds. Replaces the
  hand-added block on the unmerged `borg-checkmk-omd-backup` branch, which regenerating dropped.
- Deploy scripts for optiplex-two and smiddleware are checked in, so `pull-borg-scripts.sh`
  works on every host.

### Changed

- Generated home copies leave out `borg-survey-*` folders: their `raw/` can hold container
  environment variables.
- optiplex-three's checked-in prep script has the 3.0.0 changes, added by hand.

### Fixed

- KodiDB Borg UI wrapper SSHed to the placeholder `192.168.1.20`; it now targets optiplex-two.
- optiplex-two's checked-in prep script no longer copies decommissioned statping or dumps its
  removed `postgres` container.

## [2.0.0] - 2026-10-09

The first versioned release. Everything before it was unversioned and counts as 1.x.

### Breaking

- Prep scripts are deployed with `deploy-borg-prep-<host>.sh` instead of being copied to
  `/usr/local/sbin` by hand. It refuses the Borg UI wrapper, CRLF line endings, syntax errors
  and the wrong host, shows a diff and asks first. Copying the wrapper by mistake is what broke
  optiplex-three's pre-backup step on 2026-10-06.
- The deploy and pull scripts need the Synology share mounted at `/mnt/backups`. Without it
  they change nothing.
- Deploy backups moved to `/mnt/backups/borg-script-backups/<host>/<YYYYmmdd-HHMMSS>/`, last 10
  kept per host. Older backups in `/var/backups/borg-prep-scripts/` are not used by `--rollback`.
- Generated prep scripts differ from 1.x ones: they warn and continue when a copy or dump
  fails, where 1.x aborted the run on a failed rsync or skipped failures silently. Review the
  deploy diff when replacing a 1.x script.

### Added

- `deploy-borg-prep-<host>.sh` (generated by the survey; optiplex-three's is checked in):
  `--test`, `--rollback`, `--list`, `--backup-only`; exit 3 when the y/N prompt is declined.
- `pull-borg-scripts.sh`: downloads a host's prep and deploy scripts, the survey, the
  README, itself, `VERSION` and `CHANGELOG.md` from GitHub, checks them, and saves a dated copy
  with the commit in `/mnt/backups/borg-script-backups/<host>/github-pulls/`. Files from `main`
  go to `~/borg-backup-scripts`, files from another branch to `~/borg-backup-scripts-<branch>`.
  Only an HTTP 404 counts as a file missing from the branch; a network or GitHub error stops
  the pull with nothing changed.
- Prep script summary: timestamped progress, warnings on stderr, and a per-section table
  (files, size, time, warnings) printed at the end and saved as `metadata/prep-summary.txt`.
  In the optiplex-three script and in every generated script.
- Survey: after generating, an interactive root run on the target host offers to back up
  the installed prep script or deploy the new one.
- Survey: home directories of login users (UID 1000+ under `/home`) are listed in
  `REPORT.md` and copied into the snapshot, without `~/.cache` and without mounts inside them.
  Nothing is copied twice when homes, app dirs and compose projects overlap.
- Named volume warning. Docker named volumes are not copied into the snapshot, so Borg has to
  read Docker's volumes folder (`<data-root>/volumes`, from `docker info`). The survey lists
  named volumes in use (with containers and sizes) in a warning section of `REPORT.md` and in
  its terminal output. Every prep script run checks again, so an app added since the survey is
  caught too, and reports a `WARN` until `/etc/borg-backup/docker-volumes-in-plan` exists. That
  file lives outside the script, so deploys and regenerated scripts keep it. The checked-in optiplex-three script has the check;
  the optiplex-two and smiddleware scripts predate 2.0.0 and need regenerating on their hosts.
- optiplex-three's checked-in prep script is regenerated from its 2026-10-11 survey and matches
  the deployed one. It now covers portracker (`/volume1/docker/portracker` and a consistent
  copy of `portracker.db`), which the earlier checked-in version did not.
- `--version` on the survey and pull scripts.
- README: architecture, backup, deploy and restore diagrams.

### Changed

- rsync exit 24 (files vanished during the copy) is no longer reported as a problem.
- Directories of 10G or more, or whose size the survey could not measure in 20 seconds, are
  generated commented out and show as `SKIP` in the summary.
- k3s config, manifests and token are copied whenever they exist, even when the `k3s`
  command is not on PATH.

### Fixed

- `--name` and `--address` are validated before they are written into generated scripts.
- Two deploys in the same second no longer overwrite each other's backup.
- A directory size printed on two lines no longer breaks the generated prep script.
- The survey checklist said `chmod 700`; it is 750, matching the deploy script.
- Survey output was world-readable, including `raw/docker-inspect-all.json`, which can hold
  container environment variables. It is now written private (`umask 077`), and under `sudo`
  the output folder is handed to the user who ran `sudo`, so the report reads without `sudo`.
  An existing folder given with `--output` must be an earlier survey's folder or empty, and is
  closed up before anything is written into it; any other existing folder is refused. A
  `--from` folder from an older survey is closed up the same way.
- The report's "What Borg should back up" list repeated compose projects and app dirs that
  live inside a home directory; it now lists the home directory and names those as covered.
- The report described home copies as "excluding `.cache/`"; it now says `~/.cache` and
  anything mounted inside the home are left out.
